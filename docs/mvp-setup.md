# IntraFlow MVP 설정

## 설치

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install -e .
```

## 워크스테이션 설정

첫 번째 PC는 `새 팀 시작`을 선택하고 사용자 코드, 표시 이름, PC 이름과 NAS 경로를 입력합니다. IntraFlow는 UUIDv4 사용자·기기 레코드를 만들고 최초 사용자에게 시스템 관리자 권한을 부여한 뒤 `intraflow.local.toml`을 자동으로 작성합니다.

두 번째 PC를 연결하기 전에 첫 번째 PC 관리자가 해당 사용자를 생성하고 `동기화 > Push`를 실행해야 합니다. 두 번째 PC에서는 `기존 팀 합류`를 선택하고 NAS 연결을 확인한 뒤 발급받은 사용자 코드와 PC 이름을 입력합니다. NAS의 사용자→단위→프로젝트·파트→공개 업무 순서로 초기 데이터를 가져오며 현재 사용자의 다른 PC 업무도 최초 1회 복원합니다. 사용자 UUID와 권한은 바꾸지 않고 이 PC의 Device만 생성합니다.

같은 사용자를 여러 PC에서 사용하는 경우 작업 전 Pull과 작업 후 Push를 수행합니다. NAS revision이 달라지면 Push는 기존 데이터를 덮어쓰지 않고 차단됩니다. `동기화 > 내 업무 충돌 해결`에서 업무별로 이 PC 또는 NAS 버전을 선택하며 원본은 로컬 `conflicts` 폴더에 백업됩니다.

두 번째 PC에서 신규 사용자를 잘못 만든 경우 업무·진행·원격 반영 흔적이 없을 때만 설정 창에서 로컬 DB 백업 후 합류 상태로 초기화할 수 있습니다. 첫 번째 PC의 SQLite DB나 `intraflow.local.toml`을 복사하지 말고, 로컬 SQLite DB는 NAS 경로에 두지 않습니다.

## 실행과 자동 migration

```powershell
.\.venv\Scripts\python.exe -m intraflow.main
```

앱은 시작할 때 DB revision을 확인합니다. migration이 필요하면 `%LOCALAPPDATA%/IntraFlow/backups`에 SQLite 백업을 만든 후 최신 revision을 적용합니다. 실패하면 앱을 열지 않으며 복원에 사용할 백업 경로를 표시합니다.

## 데이터 생성 순서

1. 시스템 관리자가 단위를 등록합니다.
2. 시스템 관리자가 필수 시작일·종료일을 포함한 프로젝트를 생성합니다.
3. 시스템 관리자 또는 프로젝트 편집자가 프로젝트 기간 안에 파트를 생성합니다.
4. 각 사용자가 활성 파트 아래 자신의 업무를 생성합니다.
5. 업무 저장 시 같은 소유자를 가리키는 내부 Assignment가 자동 생성됩니다.
6. 사용자는 `내 업무`에서 진행량, 현재 메모와 개인 일정을 수정합니다.
7. `팀 업무`에서는 다른 사용자의 공개 업무와 최신 진행을 읽기 전용으로 확인합니다.

## 화면 사용 방식

- 프로젝트·파트·업무·사용자·기기·단위의 추가와 수정은 항상 별도 팝업에서 수행합니다.
- 생성 팝업은 `새 …`와 `추가`, 수정 팝업은 `… 수정`과 `변경 저장`으로 구분됩니다.
- 기본 화면 오른쪽 상세는 정의 정보를 읽기 전용으로 보여줍니다.
- `내 업무` 상세에서만 증감량, 누적 완료량, 현재 메모와 개인 일정을 바로 저장할 수 있습니다.
- `팀 업무`와 관리 화면의 사용자 업무 상세에서는 공개 진행·메모 이력만 조회할 수 있습니다.
- 현재 탭은 5초마다 로컬 DB에서 자동 갱신되며 선택·필터·스크롤과 저장하지 않은 진행 입력을 유지합니다.

### 팀 업무 보기

- `목록`: 전체 팀 업무와 공개 진행·메모 이력을 조회합니다.
- `캘린더`: 개인 업무 일정과 계획 기간을 항상 함께 표시합니다. 날짜 셀에서 업무명과 마감일을 확인하고 업무를 누르면 공개 상세와 진행 이력을 조회합니다. 한 날짜에 업무가 3개를 넘으면 `+N개`를 눌러 아래 일별 목록에서 전체를 확인합니다.
- `진행 현황`: 프로젝트→파트→업무 계층의 가중 진행률과 완료·진행 중·미시작·경고 수를 확인합니다.

파트 진행률은 하위 업무 가중치를, 프로젝트 진행률은 하위 파트 가중치를 합계로 정규화해 계산합니다. 비활성 업무와 목표량 0 업무는 기본 진행률 계산에서 제외되며 목표량 0 업무는 경고에 포함됩니다.

## 개인 자동 Pull

`개인 설정`에서 자동 Pull 사용 여부와 `1·5·10·30·60분` 주기를 저장합니다. 초기값은 자동 Pull OFF, 5분입니다. 활성화하면 앱 시작 10초 뒤 첫 Pull을 요청하며 이후 주기는 이전 Pull 완료 시점부터 계산합니다. 자동 Pull과 수동 동기화는 동시에 실행되지 않으며 NAS 오류는 화면 상태로만 알리고 로컬 저장과 Outbox를 변경하지 않습니다. 자동 Push는 수행하지 않습니다.

표시 시간대도 개인 설정에서 검색해 선택합니다. 기본값은 Windows 시스템 시간대이며 선택값은 현재 PC의 `intraflow.local.toml`에만 저장됩니다. 공유 데이터의 UTC 시각은 변경하지 않고 업무·진행 이력과 동기화 시각을 표시할 때만 변환합니다.

설정 파일 예시:

```toml
auto_pull_enabled = false
auto_pull_interval_minutes = 5
```

프로젝트 snapshot에는 프로젝트·편집자·파트만 포함됩니다. 업무, 내부 Assignment와 진행 정보는 소유자의 `users/<user_id>/public.json`에 포함됩니다. 로컬 변경은 NAS 연결 상태와 무관하게 먼저 커밋되며 동기화 실패 항목은 Outbox에 남습니다.
